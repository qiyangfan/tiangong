# 变更提案：平台 AI 入口（P1，add-platform-ai）

## Why

平台已经具备 AI 作为「普通可信客户端」的基础条件，但缺一个受控的编排入口：

- 对外契约单源已就位：OpenAPI 快照携带 `x-required-permissions` / `x-public`，可从契约机械生成
  工具目录，无需手写第二份接口清单。
- 授权与审计已服务端强制：所有写操作经 `@Audit` 留痕、错误 envelope 带 `requestId`；AI 只要走同一
  路径，就能天然获得「同权、可追溯、可回放」。
- 现状缺口：没有任何 AI 会话/动作记录、没有工具目录与权限过滤、没有确认机制与幂等控制；若直接外挂
  一个模型并授予服务账号密钥，会引入新的特权通道与不可审计的操作面。

本变更定义平台 AI 入口的**行为不变量**与最小实现范围；具体业务工具（如订单类操作）由业务仓自行
接入，本仓不预置任何业务实体与业务工具，也不定义工具注册契约。

## What Changes

- **新增能力 `platform-ai`（行为基线）**：AI 操作与人工操作同权同审计、工具目录按调用者权限过滤、
  计划与执行分离（工具返回数据视为不可信）、**所有非 GET 写操作需服务端一次性确认**、动作幂等可回放、
  AI 可关断且故障不产生半执行、会话与动作数据最小化。
- **运行时模块 `apps/api/src/modules/ai/`**：会话/消息/动作/确认票据模型（Prisma 迁移），
  POST SSE 消息端点与确认/取消/删除会话端点；新增权限点 `ai:chat`（会话与工具调用）与
  `ai:confirm`（确认写操作）。
- **传输**：消息端点使用 POST SSE，`message.delta` / `action.proposed` / `action.executed` /
  `action.failed` / `error` / `done` 事件；`done` 必须最后；流中错误使用稳定错误码，不静默中断。
- **provider 抽象**：`AiProvider` 接口 + OpenAI-compatible 流式适配器 + 测试用确定性 fake；
  单端点、无 key 池/多 provider（模型接入可由 muniu 承担）；不引入 LangChain/AgentScope 作为核心依赖，
  框架如后续引入只允许出现在适配层。
- **工具执行走平台自身 HTTP API**：以调用者 access token 调 `/api/v1/*`，经过同一 JwtGuard /
  PermissionsGuard / @Audit；禁止进程内直呼 service 绕过守卫。
- **web AI 入口**：命令面板/侧栏形态的对话与动作确认界面（懒加载，空/加载/错误态齐全），
  权限不足时入口不可用；不影响任何既有页面与人工操作路径。
- **确定性评测**：fake provider 驱动的工具选择、越权拒绝、确认过期/复用、幂等重试、注入样例回归，
  无外部模型调用即可在 CI 判定。
- **示例链路**：以 `SampleRecord` 演示「查询 → 创建（确认）→ 删除（确认）」完整闭环；不新增业务实体。

## Impact

- **DB**：新增 4 张表（`ai_conversation` / `ai_message` / `ai_action` / `ai_confirmation`）的
  增量迁移，外键级联删除，无既有表结构变更；回滚 = 删除新表与新增权限点种子，不影响既有数据。
- **API**：新增 `/api/v1/ai/*` 路由（会话、消息 SSE、动作确认/取消、会话删除），全部需要登录与
  `ai:*` 权限点；不修改既有对外契约。OpenAPI 快照随新增路由更新。
- **安全**：提示词与工具结果会发送到所配置的模型端点（支持自建兼容端点）；默认关闭
  （`AI_ENABLED=false`）；开启但缺 provider 配置时启动失败，关闭时入口不可用；会话与动作记录不含口令/令牌，日志不写对话全文
  与模型密钥；所有非 GET 动作需票据确认，票据绑定用户/动作/参数摘要。
- **前端**：web 新增 AI 面板与 i18n 文案，懒加载 chunk 计入 `size:check` 预算；miniapp 入口不在本期范围。
- **门禁**：新增 fake provider 评测用例与确认/幂等/越权/SSE 负例；现有 lint/typecheck/test/build/e2e
  口径不变，覆盖率与体积阈值不调低。
- **明确不做**：不做业务工具、不做批量工具、不做可配置策略引擎/step-up、不做多步计划、不做业务工具
  注册契约、不做 miniapp 入口、不做会话列表、不做多租户隔离、不引入 MQ/K8s、不做模型微调、
  不让模型直接访问数据库。
